# Handoff: PLOV — Android-приложение для анализа логов БВС

## Overview
Мобильное Android-приложение для чтения и расшифровки полётных логов беспилотников: ArduPilot (.bin DataFlash, .tlog MAVLink), PX4 (.ulg), DJI (.txt FlightRecord, .DAT), Betaflight / INAV (blackbox). Аудитория — коммерческие операторы (съёмка, агро) и инженеры БВС. Главный сценарий — детальный инженерный анализ полёта: диагностика, графики каналов, трек, события, параметры контроллера, сравнение двух полётов, экспорт отчёта.

## About the Design Files
Файлы в этом пакете — **дизайн-референсы в HTML**: интерактивный прототип, показывающий внешний вид и поведение. Это не production-код. Задача — **воссоздать дизайн в целевом окружении**. Рекомендуемый стек при отсутствии существующего кода: **Kotlin + Jetpack Compose** (Material 3 как база, переопределённая токенами ниже), графики — собственный Canvas-рендер или Vico, карта — MapLibre с офлайн-тайлами.

`flight-log-reader/android/` — минимальная WebView-обёртка, упаковывающая прототип в APK для демонстрации (с GitHub Actions). Её **не** нужно развивать как продукт.

## Fidelity
**High-fidelity.** Цвета, типографика, отступы, состояния и взаимодействия финальные. Данные демонстрационные (синтетический полёт ArduCopter, 14:32).

## Design system — Industry
Стиль «чертёж»: стальной синий акцент на светлом техническом фоне, заголовки Barlow Condensed, текст Barlow, модульная сетка, **квадратные углы (radius 0)**, волосяные границы 1px, «+»-метки регистрации в углах ключевых рамок (карточки, фигуры, основная кнопка). Карточки и фигуры — прозрачные (без заливки), единственный сплошной объект — основная кнопка с заливкой акцентом. Иконки — Lucide, stroke-width 1.5.

### Примитивы
- **Метка регистрации «+»**: 11×11px, позиция -6px от угла, две линии 1px цвета mk (вертикаль на x=5, горизонталь на y=5).
- **Основная кнопка**: высота 52px (нижние CTA) / 40–44px (inline), заливка ac, hover/pressed act, текст onac, radius 0.
- **Вторичная кнопка**: 1px dv, прозрачная, hover sf.
- **Чип-фильтр**: высота 32–36px, 1px dv; выбран — заливка tx, текст bg.
- **Сегмент-контрол**: сетка равных ячеек в рамке 1px dv, высота 36px; выбран — заливка tx, текст bg.
- **Чекбокс**: 20–22px квадрат, 1.5px mk; выбран — заливка ac + «✓» onac.
- **Радио**: 20px круг 1.5px; выбранный — ring ac + точка 10px ac.
- **Таблица-сетка значений**: grid с border-top/left на контейнере и border-right/bottom на ячейках (1px dv).
- Hit-targets ≥ 44px. Focus: outline 2px ac, offset 2px.

### Sheet «Импорт лога»
Затемнение rgba(0,0,0,.45), панель снизу. Handle 32×4. Заголовок 24px. Два источника (рамка, иконка-тег 40×40 «FS» / «USB»): «Файл с телефона или облака — Память, Google Диск, Яндекс Диск, Telegram»; «Полётный контроллер по USB-OTG — ArduPilot / PX4 — загрузка с SD через MAVLink FTP». «НЕДАВНИЕ ФАЙЛЫ» (4 строки: расширение, имя с ellipsis, размер). ### 02 Расшифровка
Закрыть (X), kicker «РАСШИФРОВКА ЛОГА», имя файла, «размер · источник». Блок-рамка с 4 метками: процент 72px + «%», скорость «N МБ/с», прогресс-бар 6px. Список 5 этапов (зависит от формата; см. `decSources` в логике) — квадратный индикатор: pending (mk), active (ring ac), done (заливка ac + ✓, справа результат этапа). Длительность симуляции 3.2с. По завершении: блок «ФОРМАТ ОПРЕДЕЛЁН» (рамка ac, фон ac1) + «ОТКРЫТЬ ПОЛЁТ» → новый лог добавляется в начало списка, открывается экран полёта.
Этапы DJI .txt включают «Получение ключа расшифровки — DJI API» и «Расшифровка AES-блоков» (FlightRecord v13+ зашифрован).

### 05 Экспорт и отчёт
Радио-список форматов: PDF-отчёт, CSV, KML, GPX, .param (с описанием и расширением). Для PDF — чекбоксы разделов (Сводка и борт, Карта трека, Графики каналов, Журнал событий, Изменённые параметры) + миниатюра A4 118px, перестраивающаяся по выбранным разделам. Имя файла и оценка размера. Низ: «ПОДЕЛИТЬСЯ» (вторичная) + «СОХРАНИТЬ» (основная) → toast «… сохранён в «Загрузки»».

### Toast
Снизу 24px, отступы 16px, фон tx, текст bg, 14px 500, исчезает через 2с.

## Interactions & Behavior
- Навигация: Полёты → (тап строки) Полёт; → (Импорт) Sheet → Расшифровка → Полёт; Полёты (режим сравнения, 2 выбрано) → Сравнение; Полёт → Отчёт → Экспорт. Назад — к предыдущему экрану. Android back должен работать так же.
- Плеер: тик 50мс, `t += speed·0.05 / duration`; останавливается в конце; play из конца — с начала.
- Курсор времени `t ∈ [0..1]` — единое состояние для карты, графиков, событий, плеера.
- Тема переключается кнопкой в шапке; должна также следовать системной теме.
- Единицы: metric / imperial (ft, mph, mi).

## State Management
`screen, theme, logId, tab, t, playing, speed, channels[], evFilter, q, pOnlyCh, sheet, dec{key,p}, trackBy, srcFilter, toast, sel, picked[2], cmpCh, exFmt, exSec{}` + список логов. В реальной реализации: репозиторий логов (Room), парсеры в фоне (WorkManager/корутины) с прогрессом по этапам, декодированные каналы — колоночное хранение (time + float-массивы) для быстрого рендера и даунсэмплинга (LTTB/min-max).

## Реальные данные (нужно реализовать)
- DataFlash .bin: FMT/FMTU → разбор сообщений (CTUN, GPS, BAT, VIBE, ATT, MODE, ERR, EV, MSG, PARM).
- .tlog: поток MAVLink v1/v2 с таймстампами.
- ULog: определения топиков, data/logging/parameter messages.
- DJI FlightRecord .txt: v13+ требует ключ через DJI Open API (нужен App Key); .DAT — бортовой журнал.
- Blackbox: заголовок + I/P-кадры, FFT гироскопа.
- USB-OTG: Android USB Host API, MAVLink FTP (LOG_REQUEST_LIST / FTP protocol) с SD-карты контроллера.
- Диагностика: правила порогов (VIBE > 30, клиппинг > 0, battery failsafe, падение NSats, ошибки EKF).
